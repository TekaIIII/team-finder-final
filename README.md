# TeamFinder

Текучева Екатерина Валерьевна, группа А-19-24.
Вариант 3

Это учебный проект на Django. Сайт нужен для поиска команды: можно создать
свой проект или присоединиться к чужому.

После регистрации пользователь заполняет профиль. Для входа используется
email. Если аватар не загружен, создаётся картинка с первой буквой имени.
При выборе нового файла его предпросмотр появляется сразу. Изменение
записывается после нажатия «Сохранить». Чтобы вернуть стандартный аватар,
нужно отметить «Использовать букву имени» и сохранить профиль. Если файл
аватара недоступен, вместо него отображается первая буква имени.

В профиле можно изменить свои данные, в том числе email. После смены email
для входа нужно использовать новый адрес.

На главной странице находятся проекты. У каждого есть описание, автор,
участники и статус. Автор может изменить свой проект и закрыть его.
В закрытый проект нельзя вступить.

В третьем варианте реализованы необходимые навыки проектов. Автор добавляет
нужные навыки, а остальные пользователи могут выбрать навык на главной
странице и посмотреть подходящие проекты. При вводе появляются подсказки.
Если нужного навыка ещё нет, его можно создать.

В форме проекта есть предпросмотр карточки, чтобы сразу видеть
название и краткое описание.

Для работы использованы Python 3.12–3.13, Django 5.2.4, PostgreSQL 16
и Pillow. База данных запускается через Docker Compose.

## Запуск на Windows

Команды нужно выполнять из папки с manage.py. Перед запуском базы
нужно открыть Docker Desktop.

Создать виртуальное окружение и установить зависимости:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если виртуальное окружение уже создано, первую команду выполнять не нужно.

Для первого запуска скопировать пример настроек:

```powershell
Copy-Item .env_example .env
```

Если .env уже заполнен, повторно копировать его не нужно.

В .env указать свои POSTGRES_DB, POSTGRES_USER и POSTGRES_PASSWORD.
Для локального запуска POSTGRES_HOST должен быть localhost,
POSTGRES_PORT — 5432. Значение TASK_VERSION — 3, DJANGO_DEBUG — True.

Для DJANGO_SECRET_KEY создать ключ командой и записать результат в .env:

```powershell
.\.venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

Файл .env с настоящими паролями не добавляется в репозиторий.

Запустить базу данных:

```powershell
docker compose up -d db
```

После готовности PostgreSQL применить миграции:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
```

Загрузить демонстрационные данные:

```powershell
.\.venv\Scripts\python.exe manage.py seed_demo
```

Команда добавляет три учебных аккаунта. У каждого есть свой проект
с необходимыми навыками. Повторный запуск не создаёт копии и не меняет
данные и пароли существующих аккаунтов.

Адреса для входа:

- anna.demo@example.com
- ivan.demo@example.com
- eva.demo@example.com

Пароль новых демонстрационных аккаунтов: `TeamFinderDemo!2026`.
Это обычные пользователи без доступа к админке.

Для доступа к админке создать администратора:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Запустить сервер:

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Сайт: http://127.0.0.1:8000/

Админка: http://127.0.0.1:8000/admin/

Список проектов: http://127.0.0.1:8000/project/list/

На странице списка работает фильтр по навыку через параметр skill.
Например: http://127.0.0.1:8000/project/list/?skill=Python

Остановить сервер можно через Ctrl + C. При следующих запусках достаточно
включить Docker Desktop, запустить контейнер базы и выполнить runserver.

Данные PostgreSQL сохраняются в томе Docker postgres_data.
Команда docker compose down -v удаляет этот том вместе с данными.
Аватары хранятся отдельно, в папке media на компьютере.

На Linux или macOS вместо py используется python3, вместо
.\.venv\Scripts\python.exe — .venv/bin/python, вместо Copy-Item — cp.

## Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test
```

В проекте 28 тестов. Проверяются регистрация, формы, смена email и пароля,
права доступа, работа с проектами и навыками, пагинация, создание аватаров
и повторная загрузка демонстрационных данных.

Для тестов Django создаёт отдельную базу данных.

Код пользователей находится в users, проектов — в projects,
навыков — в skills. Общие функции вынесены в common.
Шаблоны лежат в templates_var3, стили и скрипты — в static.
